```text

```

Track the route media lifecycle:

```text
Media Need
-> Candidate
-> Rights / Human Risk Decision
-> Human Decision
-> Integration
-> Visual Gate
```

Allowed states:
- media need: `HIGH PRIORITY`, `RECOMMENDED`, `OPTIONAL`, `NO MEDIA NEEDED`
- candidate: `NOT FOUND`, `FOUND`, `SEMANTICALLY VERIFIED`
- rights: `VERIFIED`, `UNRESOLVED`, `HUMAN RISK ACCEPTED`, `NOT REQUIRED FOR EMBED`
- human decision: `APPROVED`, `WAIVED`, `REVISE`, `BLOCK`, `PENDING`
- integration: `NOT INTEGRATED`, `INTEGRATED`, `FALLBACK ONLY`
- visual gate: `PENDING`, `PASS`, `REVISE`, `BLOCK`

Rules:
- key by `pageId_or_route`
- resolve against Runtime Page Inventory before treating the row as valid
- record rationale, intended placement, candidate state, rights state, Human decision, integration state, visual gate state, source/provenance, owner/defer reason, and notes where material
- never control publication, navigation, indexability, sitemap inclusion, or route creation
- never add media/layout fields to Runtime Page Inventory

Media lifecycle belongs in planning, reconciliation, and status artifacts. Runtime Page Inventory remains the publication SSOT.

Follow the authoritative GAME_SOP v2.6.2 lifecycle decision order and exact allowed state combinations. Do not independently restate or invent a second lifecycle methodology in this prompt, project docs, or implementation code.

Required execution discipline:

```text
validate exact enums
-> resolve page identity
-> branch on media_need
-> apply SOP-defined ordered state-combination rules
-> first matching rule is the single outcome
-> unsupported combination fails closed
```

Do not use fuzzy matching, substring matching, synonym inference, convenience aliases, or unsupported states.

`pageId_or_route` is subordinate to Runtime Page Inventory:

- exactly one valid match to an existing Page Inventory `pageId` or `route` is required;
- zero matches are an error;
- ambiguous or multiple matches are an error;
- the media table cannot invent routes or pages;
- a leading `/` is only a parsing hint.

`NO MEDIA NEEDED` is valid only when the page remains useful, comprehensible, and visually complete without media. It must not be accepted merely because rights are unresolved, media was inconvenient to acquire, or implementation was easier without media. Rights status and media need are separate decisions.

Use SOP's dedicated `NO MEDIA NEEDED` branch. Do not mark a no-media row unresolved merely because `candidate_state: NOT FOUND` or `integration_state: NOT INTEGRATED` reflects that no media was selected or integrated.
